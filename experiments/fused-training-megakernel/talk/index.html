01 · Fused training megakernel vs compile+CUDAGraph+ — gap study

What one training step computes

Qwen3 architecture — L transformer blocks S packed tokens · causal attention · bf16 step = forward + backward + grad-zero (optimizer excluded)
y = x·WTevery linear layer, forward — one GEMM ⇒ dx = dy·WGEMM dX — the input gradient. It feeds the next op upstream, so it sits on the step's critical path. + dW = dyT·xGEMM dW — the weight gradient. It dead-ends in the optimizer state: nothing waits on it, so it can run whenever there are idle SMs (an off-path “sink”).
the full forward math · what backward produces
  • embedding: x = Pemb[tokens] — a gather of S rows of width H.
  • rmsnorm (before attention, before MLP, and once at the end): x̂ = x · rsqrt(meanH(x²) + ε) ⊙ w — one reduction per token row.
  • qkv projection: [q | k | v] = x̂ · WqkvT, split into nq query heads and nkv key/value heads of dim D (grouped-query attention: queries share KV heads).
  • qk-norm + RoPE: per head, q ← rope(rms(q) ⊙ wq), same for k; rope rotates dimension pairs by a position-dependent angle. Fused into the qkv GEMM's epilogue in the megakernel.
  • attention: per query head, o = softmax(q·KT/√D + causal)·V — an S×S lower-triangular score matrix per head, streamed flash-style (never materialized).
  • o projection: x ← x + o·WoT (residual add).
  • MLP: [g | u] = x̂ · WguT; h = silu(g) ⊙ u (swiglu); x ← x + h·WdT.
  • head + loss: logits = x̂ · WlmT; ℓ = cross-entropy against the next token, averaged over positions.
  • backward = reverse-mode AD, right to left. CE bwd: dlogits = (softmax(logits) − onehot)/S. Every GEMM node splits into the dx / dW pair above. rmsnorm bwd reuses the saved row rstd and adds a dw row-reduce. swiglu bwd: dg = dh ⊙ u ⊙ silu′(g), du = dh ⊙ silu(g). Attention bwd re-streams the causal triangle: dV = PT·dO, dS = P ⊙ (dO·VT − Drow), dQ = dS·K, dK = dST·Q, with Drow = rowsum(dO ⊙ O).
  • Weight grads accumulate in fp32 (megakernel: pre-zeroed fp32 workspaces + atomics; baseline: AccumulateGrad kernels).

what moved long-S attention · packing law
  • The long-S bwd deficit was the C=1 causal-triangle straggler: makespan = the longest tile's serial chain. Banded chunking (split only the long tiles, per-band workspace slots) recovered ~530 µs at S=8192 bwd and ~480 µs fwd via flash-decoding partials + range-limited combine.
  • Post-banding the bwd bands are 77–83% packed (stage-units × per-stage cost / 132 blocks vs actual window) — scheduling knobs can recover ≤10%; the rest is per-stage op cost: dKV ~2.7 µs and dQ ~1.9 µs per 64-row stage ≈ 200 TF/s machine-wide vs flash ~500.
  • Bucket ratios here are trace-share ratios exactly as in the operator-gap report (megakernel on-path µs ÷ baseline active+gap µs).

measured law
Only chain-shortening pays

Caching weights in smem, cutting DRAM traffic, deeper software pipelines, and prefetch topologies were each measured slower in the 8-warp regime — the bytes already ride the latency the chain exposes. Every win came from removing dependent-latency links: epilogue fusion, register feeds, boundary removal, banding.

measured law
The ops aren't the gap

Standalone, the same mechanisms reach parity: the dX GEMM ladder closed 187.9 → 69.1 µs = 1.03× nvjet, and the attention ops are FA-class (fwd 35 µs / dKV 45 µs / dQ 30 µs ≈ flash). In-model the identical instruction pays +30–50% — the tax is the execution environment.

structural constraint
64K registers, one image

256 threads × 255 registers fills the register file exactly; every op must compile into that one point. nvjet's fastest dX shape wants 384 threads at 168 regs with a dedicated TMA-producer warpgroup, cuDNN's bprop wants warp-specialized groups — per-family register points a single kernel image cannot route across.
